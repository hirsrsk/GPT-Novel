# GPT引き継ぎメモ

## 最初に必ず確認すること

作業開始時は、必ず以下を確認する。

1. `git status --short --branch`
2. `main_novel/gpt_handoff.md`
3. `main_novel/gpt_notes.md`
4. 作業対象の本文・設定ファイル

本文の執筆・リライト・文体調整を行う場合は、プロジェクト内ローカルスキル `.codex/skills/novel-prose-guard/SKILL.md` を先に読む。このスキルは、GPT臭、視点漏れ、短文羅列、人物の聞き分けの良さを防ぐための作業手順である。

AIがWindowsでシェルを使う場合は PowerShell 7 (`pwsh`) を使う。本文確認時も文字化け防止のため、`Get-Content` は原則 `-Encoding UTF8` を付ける。

```powershell
pwsh -NoProfile
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$OutputEncoding = [System.Text.Encoding]::UTF8
Get-Content -Raw -Encoding UTF8 main_novel/gpt_handoff.md
```

PowerShellの `rg main_novel/ch*.md` はワイルドカード解釈で失敗することがある。全話検索は `Get-ChildItem main_novel -Filter 'ch*.md' | Select-String -Pattern '...'` を使うか、`rg -g 'ch*.md' '...' main_novel` の形にする。

リポジトリはこのファイルの親ディレクトリのさらに親、本文と資料は主に `main_novel`。リムーバブルディスク上で作業するため、別PCへ接続した場合でもドライブレター固定の絶対パスを前提にしない。

ユーザーは別端末でも確認しているため、本文や設定を編集したら原則としてコミットして `push` まで行う。作業前後の差分と同期状態を確認する。

## 視点管理の最重要ルール

視点漏れが多発しているため、最優先で確認する。

- 本文を書く前に、その場面の登場人物ごとに「知っている情報」「知らない情報」「推測しているだけの情報」を確認する。
- 書いた後も、地の文と台詞ごとに「これは誰の認識か」「その人物はどうやって知ったか」を確認する。
- 湊人視点で、莉緒側、紗和側、轟木側、掲示板側、サチ側の内情を知らない。
- 美月視点で、レンジが本当は悪人ではないことは分からない。配信と現地の態度から受け取れる範囲だけを書く。
- ハンドル名だけで同一人物と確定しない。
- 公式アカウントでも「本人らしい」程度に留め、必要なら公式アカウントであることだけ確認する。
- 初対面・未確認の人物名を地の文で出さない。
- 「知らない」と断れば未到達の固有名詞を出してよい、という書き方は禁止。視点人物が知らない相手は、名前ではなく「画面端の指先」「白い髪の少女」「知らない声」など、その人物が認識できる情報だけで書く。読者が疑問に思っていないことを「名前は出ていない」「正体は分からない」などと先回りして潰す文も避ける。
- 会話相手同士にとって自明な所属名、制度名、関係性を、読者説明のために台詞へ入れない。久我山父娘の会話では「天城メディカルの定期確認」と説明せず、必要なら「今日の検査、受けられそうか」のように、その会話で相手に確認したいことを言わせる。
- 台詞を一行だけ差し替える小手先修正で、次の応答が不自然になりやすい。定期検査を承知している茜に「今日は定期検査の日だ」と説明したあと「また？」と返させるような接続は避け、会話の目的ごと組み直す。

## 配信状態管理

湊人と美月は、配信中か非配信かを基本的に常に意識している。

場面ごとに必ず確認する。

- 配信中か。
- 映像は何を映しているか。
- マイクは生きているか。
- カメラだけ、マイクだけ、コメント欄だけなど部分的な状態になっていないか。
- 会話は配信に乗るか。
- コメント欄が出るなら、そのコメントは何を見聞きして反応しているのか。
- 湊人と美月がその状態を把握しているか。
- 個人名、姓、地名、近隣住民の声、コトハ情報、防犯上の内側が漏れていないか。

湊人と美月の通常運用では、情報漏れは基本的に起こさない。配信事故を使う場合も、「登場人物が配信状態を把握していないから」ではなく、疲労、混乱、不意打ち、外部要因、キャラクターの選択など、読者が納得できる理由を置く。

## ノートとコメント欄

ノート:

- 現地の販売所で野菜を買った人が残す手書き。
- 野菜の感想、買った報告、ちょっとした挨拶、現地に来た痕跡。

- 配信の音、画角、コメント欄の空気への反応を書かせない。

コメント欄:

- 配信を見ている人の反応。
- 映っているもの、聞こえている音、配信者の発言、画角、生活音へ反応してよい。
- 現地でしか知りえないノート内容や販売所内の細部を、情報経路なしに出さない。
- 英字ハンドルは多用しない。使う場合は理由を持たせる。

削除・非表示:

- コメント管理では基本的に `非表示` を使う。
- プラットフォーム側の処理や通報結果は `削除` でもよい。
- 同じ場面で `削除` と `非表示` を混在させない。
- 非表示にしてもURLがログに残る、という扱いが自然。
