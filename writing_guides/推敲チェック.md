# 推敲チェック — 新作だけで完結する手順

作成日: 2026-09-10
関連: [執筆作法.md](執筆作法.md) / [場面整理テンプレート.md](場面整理テンプレート.md)

## 使い方

ユーザーが今回依頼した範囲を確認し、対象本文、存在する前後本文、その新作の採用済み資料、必要な作法だけを読む。旧作品・別リポジトリ・過去の引き継ぎ資料を参照先に追加しない。本文の受領だけを頼まれたときは書き換えない。

未作成の設定表や場面票を、作業停止や追加承認の理由にしない。執筆・修正の依頼がある場合は、既に決まっている情報から必要最小限の場面メモを同じ作業内で整理する。未決定の重要事項は未決定と記録し、旧版や推測で確定させない。選択肢の全項目を埋めることも執筆開始の条件にしない。

## 作業の順序

1. 対象の版と変更範囲を特定する。採用済みの事実、仮案、未決定事項を分ける。
2. 物語構造、場面の確定事項、文章表現のどこに問題があるかを分類する。
3. 意図された場面の役割と、変更してはいけない事実を確認する。構造が正しい場合は、構造を再設計せず表現へ進む。
4. 問題に必要な範囲を直す。構造変更が必要なら、依頼の範囲内で場面メモと影響する後続を揃える。表現修正だけで別の結末を採用しない。
5. 修正した一文だけでなく、会話の往復、行動と反応、次の場面への受け渡しを読み直す。
6. 保存後に再取得し、意図した本文と一致するか確認する。変更対象外の資料を上書きしない。

## A. 物語構造の確認

- 場面が担う事件、関係、情報、生活時間、場所、余韻の役割は何か。意図しない重複だけを削っているか。
- 人物は現在の知識、欲求、恐怖、選択可能性から動いているか。役割のために性格が消えていないか。
- 事件を進める場面では、開始状態、行動、選択、結果がつながっているか。日常場面に対立を捏造していないか。
- 発見前の行動や比較軸へ、後から判明する正解を漏らしていないか。
- 情報が伝わる人物、時点、経路は成立しているか。読者の未開示と人物の無知を混同していないか。
- 人物の追加で他人の仕事を移しただけになっていないか。背景人物や生活描写へ事件解決を強制していないか。
- 関係の変化や回復が、出来事と時間に対して飛躍していないか。
- 続く場面がある場合、その開始状態は今の結果を受け取っているか。完結や余韻へ無理に危機を加えていないか。

## B. 場面の確定事項の確認

- 視点、時刻、場所、登場・退場、経過時間が前後でつながっているか。
- 誰が何を見聞きできるか。通信・録音・公開がある場合、その状態が一致するか。
- 呼称、二人称、愛称、役職名は関係と共有範囲に合うか。
- 信頼、苛立ち、好意、恐怖などが、意図した人物・対象へ向いているか。
- 負傷、疲労、服、汚れ、所持品、権限、技術方式が理由なく変わっていないか。
- 局所的な約束を、無関係な人物や組織まで拘束する規則へ広げていないか。
- 未決定事項を、流暢な説明で既成事実にしていないか。
- 場面の出口が、採用済みの結果と一致するか。

## C. 文章表現の確認

- 採用した語り方の知覚・内面・情報の範囲を守っているか。視点の切替を読者が追えるか。
- 誰の台詞かを、過剰な名札なしに追えるか。同一話者の連続発言が別人の返答に見えないか。
- 台詞が相手への働きかけになっているか。平時の辞書形連打や、整い過ぎた質問と正答の往復になっていないか。
- 既知情報を削り過ぎ、話題・指示対象・発話目的まで不明にしていないか。
- 抽象ラベル、定型比喩、二項対比が、具体的な行動や感情の対象を隠していないか。
- 同じ意味、固有名、動作語、短文、比喩を、重要性の保証として反復していないか。
- 痛み、身体、距離、物の位置が具体的に分かるか。機械と人間の声や、名称と表示を混同していないか。
- 行動で伝わった意味を説明し直したり、伏線の重要性を直後に解説したりしていないか。
- 全員が同じ視線、沈黙、心理分析、赤面、語尾になっていないか。
- 作法を当てはめるために、自然な短い発話、必要な反復、生活や余韻を消していないか。

## D. 修正後の読戻し

表現を変えた後、目的、選択、勝敗、開示時期、関係、呼称、感情の対象、負傷、所持品、出口が変わっていないか再確認する。台詞を一行直したら次の返答を、前提を直したら後続の理由・行動・結果を確かめる。

複数の場面が蓄積した段階では、何を繰り返し観察し、どこで文章が長くなり、何を省いているかを見る。人物ごとの解釈と行動が同質化していないか点検する。特定の作者像や固定の監査話数は指定しない。

## 指摘の記録

| 項目 | 記録内容 |
|---|---|
| 対象 | 本文・場面・版。存在する場合はコミットや内容ハッシュ |
| 分類 | 物語構造 / 場面の確定事項 / 文章表現 |
| 根拠 | 問題がある実際の記述と、照合した採用済みの事実 |
| 問題 | 矛盾、欠落、重複、誤読。好みや提案とは区別する |
| 修正 | ユーザーの意図を保つ修正内容 |
| 影響範囲 | 再確認する前後場面・設定・未決定事項 |
| 結果 | 修正済み / 保留 / 採用しない理由 |

指摘がない場合も、実際に確認した層と範囲を示す。未確認の本文まで問題なしとはしない。点検項目は自動採点や、全項目を毎回報告する義務ではない。

## 複数人・複数ツールでレビューする場合だけ使う注意

レビュー対象を、同じコミット・内容ハッシュなどで特定できる版に固定する。レビュー中に本文が変わった場合は結果をどの版に対する指摘か対応付け、現行版の修正済み項目と重複させない。読んだ版が不明な結果は、確認し直すまで採否の根拠にしない。

外部ツールの完了表示だけで内容確認済みとしない。人数、製品、セッション方式、反復回数、全員の指摘ゼロを、新作の標準的な執筆開始条件にはしない。レビュー方式を別途採用した場合も、対象と範囲を明示する。
